# SattrackSlop

An Earth satellite ground-track console (Svelte 5 + TypeScript + Vite 8) and two Moon pages (plain scripts, served from `public/`). Everything is computed in the browser; the Elysia server in `server/` is only a cache for element sets and decay histories, and the page works without it. `README.md` is the project's long account; `CHANGES-FROM-LEGACY.md` is the ledger of every intentional difference from the old static page (rows L1-L61, L66-L68 and L71-L87, L62-L65 and L69-L70 being on other branches, and the numbered rows).

## The one rule

**The computed numbers must not move.** `npm run gate` builds the production bundle and compares 67,488 values against `verification/gate/baseline.json` with `===`; it must print `BIT-IDENTICAL`. Never use `--tol`, never regenerate `baseline.json`, `verification/gate/golden.json` or the `verification/gate/ab3d/` references from the new code: they are written from the old page only (`GT_TARGET=legacy`, `--write`). If the gate moves, the code is wrong.

## Layout

- `src/lib` pure TypeScript, no DOM or globals (runs in the browser, Node and Vitest): `core` (body, SGP4 propagator, `moon`: the Moon pages' ephemeris and IAU orientation, a verbatim copy held to them bit for bit, L75), `analysis` (compute, passes, optics, Doppler), `catalogue`, `planner` (verbatim ports behind factories, `// @ts-nocheck` with `CHANGED` markers), `text` (every sentence the page says, as data), `net`, `ar`, `export`.
- `src/state` rune stores (`app`, `clock`, `custom`, `live`, `life`, `prefs`, `report`), then `src/components` and `src/scene` (three r128, imperative). Dependency direction is `lib <- state <- components`; `npm run check:deps` enforces it.
- `server/` + `shared/` Elysia cache API (`serve.ts`); the client falls back to direct fetches when it is absent.
- `data/` catalogue, world, transmitters, aliases (the picker's other names, baked by `verification/tools/fetch-aliases.js`), satcat (each object's type and purpose from CelesTrak, baked by `verification/tools/fetch-satcat.js`; re-bake it with the catalogue), WMM; `public/` the Moon pages, verbatim.
- `verification/` (CommonJS): `run.js` runs every stage; `gate/` (regress, snapshot, golden, ab3d and their frozen references), `suites/` (verify-*.js, axe, perf, screens), `reference/` (independent core.js/propagate.js and noaa-sun.js, pinned satellite.min.js), `fixtures/` (catalog.txt, WMM, behaviour and mutant lists), `tools/` (fetchers, mutation runners), `lib/` (harness). Outputs (`.build/`, `.logs/`, `screens/`, `.ab3d-out/`, `perf-last.json`, `last-run.json`) stay at the `verification/` root.
- Lazy chunks: planner, AR, report, Eden client, scene, sky data, transmitters, export, grid square, the rail's state now (`NowState`, sharing the `maidenhead` chunk with the grid square), the sky plot's live layer (`sky-live`, asked for the first time the clock is inside the pass it shows), the pass list's Sun times and their words (`suntimes`, asked for once there are passes), the pass list's filter (`PassFilterBar`, asked for once there are passes, and its panel `PassFilter`, at the first press), the one-pass calendar's press (`pass-ics`, at the first press, with the export chunk; it shares the `share` chunk with the AR view), the picker's "decayed now" marks (`decayed.svelte`, the first time the list opens; never under `?tle=embedded`), the watchlist star's press (`watch-press`, at the first press), the picker's other names (`alias`, and its table `aliases`, asked for together the first time something is typed; not on opening, which verify-visitor's total counts), the decay comparison (`DecayCompare`, with its store, chart, view controls (range, quantity (nine, the inclination and the RAAN offset from the selected spacecraft among them, L68), zoom, reading slider), words and style, at the first press of "Compare with other spacecraft", or when the Decay section comes near with the panel left open; the report's chunk holds only the button, its two sentences and the import, and imports nothing of it), the decay history's direct fetch (`direct-history`, at the first history request that has to ask CelesTrak itself; it reads the page with `Lifetime.readPlot`, so CelesTrak's page reader is in the `lifetime` chunk, which the first screen fetches anyway, and not a chunk of its own, which cost the first screen more than its ceiling allows). The realistic globe (`realism`, asked for by the scene when the "Realistic" surface is chosen, L71; it also holds the 500 m tiles' window `realism-detail.ts`, the sky `realsky.ts` and the Moon's ephemeris `lib/core/moon.ts`, L74-L75, and fetches GIBS tiles only close up), the close-up (`closeup`: the craft's pass, three's glTF loader and the card, at the first press of the Close-up camera, L72, with the reader's flight settings `state/attitude.svelte.ts`), its flight panel (`flight`, at the first press of "How it flies…", L77; the spin's three rates are on the card, in `closeup`; the pose arithmetic, `lib/models/attitude.ts`, is the shared `attitude` chunk) and a reader's model panel (`uploads`, at the first press of "Your model…", L73); `three.module` is a chunk of its own since the scene and those two share it, `look-glsl` is theirs, and `models.svelte` (the reader's models in IndexedDB) is fetched with the close-up and by Forget. The catalogue's colours by class (`catcolour`, with `lib/catalogue/classify.ts`, at the first choice of a colouring under Layers → Catalogue, L76) and CelesTrak's table for them (`satcat`, `data/satcat.json`, asked for by "By type" and "By purpose" only). The flat map (`map-chunk`: `MapView.svelte`, `draw-map.ts`, `map-layers.svelte.ts`, `MapKey.svelte`, its Layers panel and full screen, L86), the first time the Map tab is shown; the key's fixed rows and the readouts stay in the stage. A lazy chunk must import nothing from the entry (not `app`, not `globe-state`, not `ui/Rich.svelte`), or the bundler splits the entry's shared modules into chunks of their own: the close-up is handed the globe and the app in `attach()`; and a Svelte feature only a lazy component uses (`{#await}`, `bind:value` on a select) lands in `index-client`, which the entry counts. The entry the page cannot start without is ~89.3 KB gzipped in four files (91.74 by L85, 89.31 once the map left it with L86; 2.7 KB left under the budget) (`index`, `index-client`, `rich` and `rolldown-runtime`, the bundler's helper); `verify-visitor.js` holds it to the 92 KB budget (`ENTRY_BUDGET`; 90 KB until L72), which binds, and the first screen's JavaScript to a ceiling 5 % over the 327.9 kB it was re-measured at with L71-L73: anything added to the entry, the scene, the lifetime chunk or the Decay panel's chunks must be paid for there.
- The test facade (`window.__gt`, `Orbit3D`, ...) is a lazy chunk installed only when `window.__GT_TEST__` is set; the entry chunk must not contain it. It also sets the old page's globe switches (6 h trail, catalogue, footprint, observer's pin), since the page opens plain since L80 (`window.__GT_DEFAULTS__` keeps the page's own).

## Commands

`npm run dev` (Vite + API), `npm run build`, `npm run preview`. `npm run test:fast` (types, layers, unit, fast browser stages), `npm run test:all` (every stage, one table). Single suites: `npm run gate`, `visitor`, `custom`, `planner-ui`, `ar`, `ar-snap`, `ab3d`, `golden`, `layout`, `axe`, `perf`, and the rebuild's own `realism`, `closeup`, `models`, `catcolour` (see README, "Running it"). `GT_TARGET=new|legacy` picks which page a suite drives (default `new`; the old page is in git at the tag `legacy-earth-console` and is checked out for a suite with `git worktree add legacy legacy-earth-console`); `GT_DIST=<folder>` picks the build folder.

## Working rules learned the hard way

- Never run other browsers while a full run is going: pov, ab3d, planner-ui, the AR suite and ar-snap are timing-sensitive. A failure that passes alone is a load flake only after you have run it alone.
- A new fact the page states goes into `src/lib/text`, a difference from the old page goes into the ledger the same commit, and a suite that asserted the old behaviour is changed in that commit with the reason.
- Verbatim ports (`plannerui.ts`, `arview.ts`, `globetex.ts`, `orbit3d.ts`, ...) keep the old arithmetic order and comments; edit them only at marked `CHANGED` lines.
- Do not push, deploy, merge, or install system software without being asked. Stage specific paths, never `git add -A`.
- Scripts and files with backslashes written through a shell heredoc lose them: write such files with the editor tools.
