# Changes from the pre-rewrite Earth console

The rewrite keeps every computed number identical (`npm run gate` must print BIT-IDENTICAL) and otherwise changes
only what is listed here. If something differs from the old page and is not on this list, it is a bug.

Status: **applied** = in the code now, **planned** = decided in the plan, not yet made.

## Behaviour and data

| | Change | Why | Status |
|---|---|---|---|
| 1 | Transmitter lookup uses the NORAD id as a number. The old page passed the zero-padded id (`"01804"`) to a table keyed `1804`, so the 20 satellites with NORAD < 10000 that have a downlink never showed one. | Verified bug; the data was always there. | applied (tests/lib/places-and-transmitters.test.ts) |
| 2 | One Sun model. The old code carried four; the 3D light omitted the `-4e-7·n` obliquity-rate term (about 0.004°). | The scene light moves by a hair; tests bound it. | not done: the globe keeps its own series for its light, moved as it was, so that the scene stays comparable to the old page's pixel for pixel; revisit at M9 |
| 3 | The 2012 city-lights mosaic is baked into the shipped imagery like the Blue Marble, so the default globe never waits on NASA GIBS. Only the dated "yesterday's clouds" layer is still fetched. | The default surface blocked on a 3-8 s request. | planned: needs a download of the mosaic from GIBS, which waits for a yes. Until then see 11 |
| 4 | `file://` opening is dropped for the Earth console (ES modules and workers need an origin). The Moon pages still open from disk. | Consequence of a bundled app. | applied |
| 5 | The page makes no request to Google Fonts, cdnjs or any CDN. satellite.js 6.0.1 and three r128 are bundled from npm at exact versions. | Speed, privacy, no third-party blocking. | applied |
| 6 | `?tle=embedded` is unchanged and still fully offline. | Reproduces the README figures (KNACKSAT-2: 899.7 s over 2 passes). | applied |
| 7 | Element sets and decay histories are asked of the page's own data-cache API first (`/api/tle/<n>`, `/api/history/<n>`), and of CelesTrak and its mirror directly only when no API answers as itself (no `x-gt-api` header, a 404 or 5xx, offline, a rate limit). A page with no API behind it (the production deploy until a host is chosen) behaves as the old page did, after one failed probe per ten minutes. Under `?tle=embedded` nothing is asked, not even the API. | N visitors cost CelesTrak one request, not N. | applied (verify-refresh runs both ways: `refresh` with the API down, `refresh-api` with it up) |
| 8 | Network deadlines cover the body as well as the headers, in the browser and on the server. The old page cleared its timer when the headers arrived, so a stalled body could hang an element-set check. | A hung read looked like "still checking" forever. | applied |
| 9 | The API refuses an element set whose epoch is more than 3 days past its own clock, and one older than what it already holds ("forward only"), and never serves a record past its TTL because a source is down (no stale-if-error). A history that arrived but is unusable (`empty`, `outside`) is cached as an answer; failures never are. | One bad set must not pin the floor above every correct set to come, and an error must not be cached for everyone. | applied |
| 10 | When the API answers a decay-history request with its own structured 504, the browser does not then wait out a second 70 s on the direct path. Every other API failure falls back to the direct fetch. | The old worst case was 70 s plus 75 s. | applied |
| 11 | The globe opens on the shipped Blue Marble (surface `marble`), not on "Blue Marble & city lights" (`night`), whose lights are a NASA GIBS mosaic fetched at every start. The lights are one choice away in the Layers panel, and a saved choice (`gt.surface`) wins. | Until the lights are baked (3) the default page would make a third-party request on load, and `?tle=embedded` would not be offline. | applied |

## Verification

| | Change | Why |
|---|---|---|
| A | The suites open the page over http through `verification/lib/harness.js` instead of `file://`, and answer the two cdnjs scripts from local copies whose sha512 matches the page's pins. | A bundled app cannot load from disk; a clean run no longer depends on cdnjs. |
| B | `regress.js` / `snapshot.js` run in-process. `baseline.json` can only be rewritten with `GT_TARGET=legacy` and `--write-baseline`. | The old `.replace()` on snapshot's source silently overwrote the baseline if its `OUT` line was reformatted. |
| C | `gate:lib` runs the bundled library in a blank **Chromium** page, not in Node. | The baseline was made in Chromium; the same bundle in Node 23.5 differs in 364 values by up to 1e-14 (V8 `Math` differences). In Chromium it is BIT-IDENTICAL. |
| D | `verify-planner` V15 ("the four drag functions throw when Lifetime is absent") is skipped, out loud, for the module build. | "Lifetime absent" is a state of the classic globals only; an import cannot be absent. The caller's failed dynamic import is covered by the browser suites. |
| E | `verify-advisor` / `advisor-copy-checks`: the "is an IIFE over (window or globalThis)" and "attaches to window" checks are skipped, out loud, for the module build; the purity scan and "Professor appears once" now scan the verbatim TypeScript source. The bare-context load is replaced by "it imports nothing". | An ES module is already strict and scoped; the substantive invariants (no DOM, clock, storage; one definition of the label; the words stand alone) are kept. |
| F | `verify.js` CHECK 5 is split: 5a pins the Earth console by exact version + lockfile tarball hash (and `tests/lib/satellite-parity.test.ts` proves the npm ES build equals the vendored UMD bit for bit); 5b keeps the Moon pages' three.js SRI, checked against npm's file. | The new build has no CDN tag to pin. |
| G | `npm test` is replaced by `verification/run.js`: fail fast only on the numbers, then run every other stage and print one table. | The `&&` chain hid every stage after the first failure. |
| H | Known and unchanged: `verify-ar` fails two date-dependent checks on days when the highest pass is near the zenith. Fixed in M8 with a fixed clock and a pass of 20-60 degrees. | Pre-existing; not caused by the rewrite. |
| I | New tools, not ports: `verification/screens.js` takes the review pictures (4 viewports x 2 themes, plus the phone's open sheet, the picker and the window popover) and `verification/axe.js` sweeps axe-core over 5 viewports x 2 themes x 3-4 states. M9 enforces the legacy page's count as the ceiling for axe; the legacy count has not been measured yet. | The design review needs pictures; the shell must not ship worse accessibility than the page it replaces. |
| J | The suites that drive the page now do it through `verification/lib/harness.js` helpers (`pick`, `pickExact`, `clickWindow`, `siteForm`, `setSite`) that open a popover if it is shut and then use it, and do nothing extra on the old page, so one file runs against both builds. What the old page kept on the entry (`__prov`, `__next`) is `__gt.live` (`prov`, `setProv`, `next`, `makeDue`). The observer is a value, replaced when it moves, so a suite reads `__gt.OBS` afresh after a move. | The rebuilt controls are popovers, and the entry is immutable. | applied |
| K | `verify-timeline` and `verify-site` skipped, out loud, the checks that need the 3D scene (the trail switch: 4; the pin, the camera label and the globe's key: 4) until the scene was rebuilt. They run now, unchanged. `run.js` gained a `refresh-api` stage (the same suite with `GT_API=up`). | Eight checks were not being made. | applied (M6) |
| M | **Prose parity.** `verification/golden.js` captures the report's words from the old page - the element cards and notes, the osculating and derived values and what is said under them, the headline, the pass table and list, the facts under the sky plot, the downlink options, the countdown (at the window start and at the last pass's culmination), the provenance, the decay panel's offer, the Method notes and the 28 terms - for the 38 baseline spacecraft x {24 h, 72 h} x 3 observers (Bangkok, Svalbard, Adelaide), at a frozen clock, into `verification/golden.json` (2.2 MB, made only from `legacy/`). The rebuilt page has to say the same, character for character, with a no-break space kept as a no-break space and an abbreviation's expansion, a link's target and a bold phrase kept as marks. Differences that are intended are listed in `verification/golden-diffs.json` with their reason; everything else fails the stage. `golden-lite` (5 spacecraft, one observer) is in `test:fast`; `golden` is the whole matrix. | The numbers are guarded bit for bit; the sentences around them are not numbers, and a rebuild that re-types them quietly changes what the page claims. |
| N | **Scene parity.** `verification/ab3d.js` captures the old page's 3D scene in 16 states (the boot state, both local surfaces, the elements and sky layers, the three camera modes and a dragged one, a zoom, the lens, no Earth, the trail off and the whole day, no catalogue dots, another observer, a spacecraft in view) at a frozen clock with software WebGL: the rendered frame, and an inventory of the scene graph (every object's type, visibility, geometry, material, colour, uniforms and world matrix, and the renderer's counts). The rebuilt page is compared with it: exact for the inventory (floats to 1e-6), exact then tile by tile for the pixels. The reference is made only from `legacy/`. | The numbers are guarded bit for bit and the sentences character for character; the picture needed a guard of its own, since the globe is a verbatim port that has been wrapped, fed differently and paced differently. |

## Look and interface

| | Change | Why | Status |
|---|---|---|---|
| L1 | The console is a **Stage** (Map and Globe tabs) beside an **Answer rail**, with the **transport** docked under both; the report follows with a sticky sub-nav that keeps the `#sec-*` anchors. | One answer first; the old page spread controls over seven overlays. | applied (the Globe tab is a placeholder until M6) |
| L2 | The rail is a column (>= 1100 px), a foldable panel under the stage (720-1099), and a bottom sheet whose peek is the headline and the countdown (< 720). One copy of its content is mounted, so each id exists once. | A phone gets the picture first and the answer one tap away. | applied |
| L3 | The window controls (+-1 d, +-6 h, start, Now, Epoch, span) live in a **Window** popover in the transport instead of a permanent bar. Their ids are unchanged (`winStartIn`, `winPrevD`, `tpnow`, ...). The window opens at the reader's clock, not at the set's epoch (the old page's behaviour is kept under `?tle=embedded`). | Compact console; "when can I see it tonight" is the usual question. | applied |
| L4 | A manual light / dark / auto toggle (saved under `gt.prefs`); the theme is set in `<head>` before first paint. The globe and the map's sea stay dark in dark mode and light in light mode as before. | The old page followed the system with no way to override it. | applied |
| L5 | Type scale with a 12 px floor (the old page had 15 sizes and about 57 rules at 11 px); fonts are self-hosted (IBM Plex Sans and Mono, Archivo variable, Latin). `--warn` is new so orange means only "in view". `--contact` is `#A8600D` in the light theme (was `#B4670F`): 4.8:1 as text on white instead of 4.3:1, which axe flagged. | Legibility, speed, privacy, AA contrast. | applied |
| L6 | The picker's options are plain `li[role=option]` (no button inside an option) and its "no match" and "N more" notes are outside the listbox. Suites that read `#satlist li.note` use the new `p.note`; the "Plan an orbit" row returns with the planner (M7). | axe: nested interactive controls and non-option children in a listbox, 80 + 1 + 1 nodes per open picker. | applied |
| L7 | Permalinks: `?sat=<NORAD>&span=<hours>&site=<lat,lon>&tab=globe or map` alongside the existing `?tle=embedded`. | Share a view. | applied (`t=` for a time is not built) |
| L8 | The headline's sub-line is the old page's own sentence (how long in view, over which window, from when in the observer's time, and which element set's epoch), and the exact seconds and the pass count are a line of their own under it (`#totalexact`, "899.7 s over 2 passes"). | The README's figure stays on the page; the sentence that says which window and set it came from is unchanged. | applied |
| L9 | The selected pass's facts (times, culmination, naked-eye verdict, brightness, Doppler) and the downlink controls sit under the sky plot in the rail's Passes tab; the CSV and calendar buttons sit under the pass list, and the report's Passes section holds the full table. All three tabs of the rail stay in the page, the unselected ones hidden, so every id exists once and can be found. | One place per fact; the old page had the buttons under the table, a screen away from the list. | applied |
| L10 | The spacecraft picker closes after a choice whether or not it loaded, and a refusal is said in the note under the bar (`#loadnote`). The old combobox put the current name back in its field. | There is no field to put it in: the title names the spacecraft on screen. | applied |
| L11 | Keys: Space plays and pauses, the arrows step the clock a minute (Shift: an hour) and stop it, `[` and `]` halve and double the rate, `g` and `m` show the Globe and the Map. A key a focused control has a meaning for (a button, a slider, a field) is left to it. | Keyboard use of the transport; checked in verify-slice. | applied |
| L12 | The age of an element set and when it was last checked are read against the real time of day, refreshed every 30 s and when the tab returns (`wall.svelte.ts`), not against the transport's clock, which can be scrubbed to any instant. | "epoch 23 days old" must keep meaning the present while someone scrubs a day ahead. | applied |
| L13 | The window controls and the observer form read their fields from the elements when they are used, and the transport's two sliders listen at the element rather than through the framework's delegation. | A synthetic event that does not bubble (a script, an assistive technology) reaches an element's own listeners and never the document's. | applied |
| L14 | The report is Orbital elements, Ground track, Passes, Decay, Method and Terms, with the old page's `#sec-*` anchors and order. The "Element set" section (the two raw lines and where they came from) is the rail's Source tab and has no section of its own; the Professor's notes (`#sec-prof`, and the link to it in the elements hint) return with the planner (M7). | One place per fact: the provenance was in the rail and again in the report. | applied |
| L15 | The ground-track section does not draw a second map. The map is the stage's Map tab (one map, one clock, at the top of the page); the section says what the track covers (the window and the revolutions in it) and has a button that shows the map. The map's key and its readout labels went with it, in the same words. | A second copy of the map drew the same picture a screen further down. | applied |
| L16 | In the Passes section the sentence "Click a row to plot that pass's sky track here, and in the Sky track panel at the top of the page." is dropped: the heading above the table says it ("click a row for its sky track") and the plot is beside the table. The CSV and calendar buttons are under the rail's pass list, not under the table. | The sentence repeated the heading and described a layout that has changed. | applied |
| L17 | The Terms section has a search box. A term that does not match is hidden, not removed, so a link to any `#t-*` anchor still lands (the Professor's notes link to `#t-sso` and `#t-ltan`; a test checks that every `#t-` link in the source finds a term). | 28 terms are a lot to read for one word. | applied |
| L18 | The decay chart, the drag model and the sentences that read a history are a chunk of their own (about 8 KB gzipped), fetched when the Decay section is within a screen or two of view or a forecast exists. A forecast already in the cache therefore appears a moment after the spacecraft does, and the chart's canvas is empty until the chunk arrives. The offer to fetch, the wait and the failure words are in the main chunk. | The main chunk is at 85 KB gzipped, under its 90 KB budget; most visits never scroll to the decay. | applied |
| L19 | The downlink controls always show the spacecraft on screen's own. The old page repainted them only for a pass, so a spacecraft with no pass in the window was left showing the previous spacecraft's downlinks, and the golden capture reads them only where there is a pass. A table that lists one frequency twice (one per mode: TEN-KOH on 437.390 MHz) shows both options, and the last of them is the one selected, as before. | A leftover, not a feature. | applied |
| L20 | The globe is the stage's first tab and what the page opens on; the flat map is the second. Both stay in the page, the one not chosen hidden, and the map is drawn only while it is showing. Where WebGL is not available the page opens on the map instead (unless the reader chose a tab), and the globe says so. | The old page showed the globe on top and the map in the report. | applied |
| L21 | The camera (Free, Satellite, the observer, POV), the trail (Off, 30 m, 1 orbit, 6 h, 24 h) and the Layers panel are two rows and one button over the globe, with the old ids and data attributes. The Earth and Catalogue switches moved from the transport bar into the Layers panel with the surface choice, the footprint and the sky layers. On a phone the controls are a strip along the bottom, so the clock keeps the top. | Seven overlays at pixel positions collided on a short screen. | applied |
| L22 | The scene draws only while it can be seen and something is moving: nothing while the Map tab or another part of the page is showing, ten frames a second while only real time is passing, thirty under a clock up to 60 times faster, every frame while the reader is dragging or the clock is faster still, and none when the clock is stopped and nothing has been touched for two seconds. Anything that calls into the scene wakes it. The old page drew sixty frames a second whatever was happening. | A parked console cost a core. Measured: 10 frames/s at real time, 0 when paused and idle, about 56 under the pointer (software WebGL). | applied |
| L23 | The catalogue's 2,158 dots are propagated when the clock has moved a second from where they were last placed, not on every third frame; the cull and the colours, which follow the camera, still run each pass. | A low orbit covers 7.6 km a second, a third of a pixel at the opening zoom; the profile of the old page put this loop at about 12 % of a core at 60 fps. | applied |
| L24 | The star catalogue and the constellation figures (64 KB, 29 KB gzipped) are a chunk of their own, fetched beside the scene's code; the stars appear a moment after the globe does. The scene's chunk is 152 KB gzipped (three.js r128 is bundled as the forty-odd members the scene names, not whole). | The sky is not on the critical path. | applied |
